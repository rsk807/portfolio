Case File 001

Omniscient — Digital Forensics & Cybercrime Investigation Platform PATENT PUBLISHED

Classification Digital Forensics & Cybercrime Investigation
Status Patent Published
Patent ID 202521077464
Authority Indian Patent Office (InPASS)
Publication PATENT RECORD →
Source Explore Omniscient

Question

How can digital forensics analysts automate intelligence extraction from fragmented social channels and API responses without exhausting manual investigation hours?

Background

Cyber intelligence extraction involves navigating massive API structures, rate-limiting, and noisy user streams. Solving this is vital to drastically reducing the time spent by digital forensics investigators when hunting operational threat vectors.

Objective

To build a digital forensics platform leveraging LLMs and API reverse engineering to parse channels and extract actionable threat intelligence.

Approach

Decoupled architecture separating web scraping and reverse-engineered API gateways from LLM reasoning components. Rather than querying models on raw noise, we pre-process headers and structure JSON datasets to optimize token usage.

Title: A System and Method for Dynamic Cybercrime Investigation Using Automated Data Extraction and Analysis

System Specs

  • Cache Redis
  • Patent Published InPASS
Omniscient Forensics Processing Flow [ API Gateways ] ➔ [ Data Sanitization Block ] ➔ [ LLM Inference Engine ] ➔ [ Forensic Report ] DIAGRAM REF: SK-OMS-01 // PATENT PUBLISHED

Design Decisions // Trade-offs

We chose sandboxed headless scraping nodes rather than high-resource browsers to prevent detection and tracebacks during automated runs. Concurrency queues managed via Redis ensured that investigator time is reduced from hours to single-digit minutes.

Lessons Learned

LLM hallucinations on raw data dumps are mitigated by structuring raw scraped arrays into strict key-value JSON formats prior to model execution.

* Field note: Forensics data parser latency minimized to 8.2s per log sequence. Published Indian Patent Application (ID: 202521077464).

Case File 002

RakshaNetra — Proactive Data Leakage Prevention for LLMs

Classification Cybersecurity + Privacy + Enterprise
Status Prototype Validated
Year 2026
Execution Edge Local Browser Proxy
Source Explore RakshaNetra

Question

How do we prevent sensitive enterprise metrics, API tokens, and user credentials from leaking to public LLM endpoints through web browsers and API relays?

Background

Organizations deploying third-party generative models risk exposing intellectual property. Sanitization must occur at the client edge prior to packet transmission.

Objective

Build a local-first browser interception proxy that redacts sensitive text patterns and images in real-time.

Approach

Client-side interception via service workers and browser proxy layers. Intercepts user prompts, processes them through local lightweight patterns, and sanitizes data.

System Specs
  • Stack MERN
  • Proxy Core Service Workers
  • Redaction Regex & Local Model
  • DB MongoDB
RakshaNetra Interception Flow [ User Input ] ➔ [ Service Worker Hook ] ➔ [ Local Regex / Classifier ] ➔ [ API Request ] DIAGRAM REF: SK-RKN-02
Click to Zoom Spec

Design Decisions // Trade-offs

Prompts are sanitized entirely inside sandboxed JS workers before packet serialization. No data is stored outside local memory to prevent interception. Highly optimized redaction patterns run in under 14ms.

Lessons Learned

Regular expressions are highly efficient for structured tokens (API keys), but machine learning classifiers are required to redact unstructured natural language details.

* Field note: Local redaction sanitizes sensitive inputs under 14ms latency.

Multi-Agent
Case File 003

BidForge — Automated RFP Multi-Agent System

Classification LLM + Multi-Agent Automation
Status Prototype Deployed
Year 2026
Engine Core LangChain / Gemini 2.5
Source Explore BidForge

Question

How can organizations accelerate massive RFP (Request for Proposal) analysis and generate precise, contextually aligned bidding documents without hours of manual compilation?

Background

RFP processing involves digesting thousands of requirements and semantic cross-referencing against product lists, leading to high administrative latencies.

Objective

Architect a multi-agent AI system automating requirements exploration, inventory matching, and document synthesis.

Approach

Pipeline separating analysis into modular steps: Parse, Explore, Summarize, and Generate. Employs LangChain and Gemini 2.5 Flash agents combined with vector index matching.

System Specs
  • Engine Bun / TypeScript
  • Agents LangChain / Gemini
  • Retrieval MongoDB Vector
  • Storage AWS S3
BidForge Multi-Agent Pipeline [ RFP Inputs ] ➔ [ Parse / Explore Agents ] ➔ [ Vector Semantic Search ] ➔ [ AWS S3 PDF Generation ] DIAGRAM REF: SK-BDF-03
Click to Zoom Spec

Design Decisions // Trade-offs

Utilized Bun's native TS execution and asynchronous multi-agent orchestration to reduce proposal generation times from days to single-digit minutes. Vector search uses HuggingFace embeddings inside MongoDB.

Lessons Learned

Multi-agent coordination requires strict JSON response format schemas; unconstrained LLM answers will break the downstream compilation pipelines.

* Result: RFP analysis processing latency reduced to under 45 seconds.

Case File 004

VACARS — Voice Assisted Context Aware Response System SPRINGER JOURNAL

Classification IoT + AI Assisted Smart Helmet System
Status Published in a Springer Journal
Publication Springer Journal Publication
View Publication Springer Journal Article ↗
Year 2026
Source Explore VACARS

Project Overview

VACARS (Voice Assisted Context Aware Response System) is an IoT + AI assisted smart helmet system engineered to deliver context-aware heads-up assistance, environmental awareness, and real-time obstacle recognition without dependence on high-latency cloud relays.

Technologies

Engineered using Raspberry Pi, offline speech recognition engines, OpenCV MobileNet-SSD edge object detection, Python / C++ thread pools, and low-latency motor-driven faceplate actuators.

Architecture

Decoupled concurrent architecture balancing sensory inputs, edge acoustic processing, and video frame inference. Offloads continuous frame buffers to hardware-level DMA buffers to sustain real-time processing threads without thermal throttling.

Research Impact

VACARS was published in a Springer Journal, establishing empirical metrics for edge AI inference stability and hands-free rider safety loops in safety-critical vehicle environments.

Publication Record

Publication: Springer Journal Publication

System Specs
  • Hardware Raspberry Pi

  • Journal Springer Journal
VACARS Edge Interface Diagram [ Audio Inputs ] ➔ [ Threads Balance Pool ] ➔ [ MobileNet-SSD Frames ] ➔ [ Actuators Drive ] DIAGRAM REF: SK-VAC-04 // SPRINGER JOURNAL

Design Decisions // Trade-offs

Component-oriented modular layout separating voice handlers from physical motor actuators. Real-time frames are offloaded to hardware-level DMA buffers to sustain real-time processing threads without thermal throttling.

Lessons Learned

DMA frame offloading is critical when combining multi-modal networks on single-board hardware, reducing CPU cycles by over 30%.

* Prototype confirmed: Voice-actuated faceplate triggers motors under 350ms. VACARS was published in a Springer Journal.
